# QA report — KekkAI telemetry dashboard

**Target:** `http://127.0.0.1:8787` (local, `kekkai serve`)
**Tier:** Standard
**Date:** 2026-09-24
**Result:** Pass, with one dimension unverified.

## Coverage gap — stated, not estimated

The Claude-in-Chrome extension was not connected during this pass, so **no rendered-DOM,
visual, or runtime-console checks were performed**. What follows is static analysis of the
served HTML, CSS, and HTTP responses, plus API-level verification of the data the page
consumes. Three standard-tier items remain unverified and are not claimed as passing:

| Unverified | Why it needs a browser |
|---|---|
| Visual review at 375 / 768 / 1440 px | Requires rendering; the CSS was inspected instead (see below) |
| Runtime console errors | Requires executing `app.js` against a live DOM |
| Poll behaviour and live re-render | Requires a running page over several 5 s intervals |

The API those three exercise *was* verified directly, so the data contract behind the page is
known good even though the page's rendering of it is not.

| Unknown path | 404, not a soft 200 |
| Bind address | loopback only by default |

HSTS and `X-Frame-Options` are absent and intentionally so: this is a loopback HTTP service,
HSTS is meaningless without TLS, and the CSP already denies framing sources.

## Responsive — CSS inspection only

- Tiles use `grid-template-columns: repeat(auto-fit, minmax(170px, 1fr))`, so they reflow from
  six across to one without a breakpoint.
- The decisions table is wrapped in `overflow-x: auto`, so it scrolls rather than forcing the
  page wide.
- All large pixel values are `max-width` (1100 px container, 460 px reason column), which caps
  rather than forces width — an earlier automated pass flagged these as overflow risks, which
  was a false positive in the checking regex, not a page defect.
- `prefers-color-scheme: dark` is handled with a full token set.

**Still requires visual confirmation at the three viewports.**
